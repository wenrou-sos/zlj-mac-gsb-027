# 御足堂 · 连锁足浴总部分店管理平台

一个面向连锁足浴品牌的「总部 — 门店」一体化管理系统：总部统管**项目定价 / 会员体系 / 技师提成**，门店执行**收银交班 / 双签确认**，每日营收自动汇总至总部看板。

零第三方运行时依赖（Node.js 内置 HTTP 服务 + JSON 持久化 + 手写 SVG 图表 + Canvas 手写签字），`npm start` 即用。

## 快速开始

```bash
npm start          # 启动 http://localhost:3000
npm run reset      # 清空数据，下次访问自动重新生成演示数据
```

| 角色 | 账号 | 密码 | 说明 |
| ---- | ---- | ---- | ---- |
| 总部运营中心 | `admin` | `123456` | 定价 / 会员 / 提成 / 门店 / 全品牌看板 |
| 门店店长 | `store1` ~ `store6` | `123456` | 分别对应 6 家门店 |

系统已预置 **6 家门店、35 名技师（含培训档案、调动、离职）、60 名会员、近 35 天 420 个班次 / 2500+ 上钟单 / 560+ 笔充值** 的演示数据；每个门店当天晚班处于"进行中"，可直接体验交班签字流程。

## 功能一览

### 总部端
- **品牌总览看板**：全品牌今日/近7/30/35天总营收；35 天营收&充值双轴趋势；各门店营收排行与今日实时排行；各品类/项目销售占比（环形图 + 明细）；现金/刷卡/会员卡收款构成；会员充值总额、卡内沉淀余额、技师提成、折扣让利。
- **项目与统一定价**：项目目录、时长、挂牌价、上下架由总部统一维护，**改价即时下发全部门店**；自动展示各会员等级折后价。
- **会员体系**：4 级会员（普通/银/金/钻）等级折扣、升级门槛、各等级"充值赠送方案"统一配置；全项目折后价矩阵。
- **技师提成标准**：`项目 × 技师等级（初/中/高/首席）`提成比例矩阵，提成按**实收金额 × 比例**随单自动核算；可一键恢复基准比例。
- **门店管理**：开立新店（同步生成店长登录账号）、编辑、停业。
- **技师档案**：全品牌技师名册、入职登记（培训/考核记录、擅长项目）、跨店调动、离职办理，调动留痕可追溯。
- **会员名册**：跨店检索、等级调整、账户台账（充值/赠送/卡扣消费流水）。

### 门店端
- **门店看板**：本店今日/近7/30 天营收与充值趋势、收款构成、近期交班报表。
- **交班工作台**：
  - 开班 → 登记上钟单（项目/技师/人数/会员/收款方式，自动算会员折扣价与技师提成）、会员充值（按等级方案自动带出赠送额）；
  - 实时汇总**本班接待人数、现金/刷卡/会员卡各收多少、技师上钟明细、充值明细、提成合计**；
  - 撤单自动退款回会员卡，撤销充值自动扣回余额；
  - **交班双方手写签字确认**（Canvas 手写签名，交班人先签、接班人复核后签，签字后报表锁定不可改），支持打印纸质交班单。
- **交班报表**：按日期/状态检索历史班次，查看与打印含双方签名的完整报表。
- **本店技师 / 会员 / 调动记录**：门店仅能操作本店数据，跨店调动仅总部可执行。

## 权限模型

- 门店端所有数据操作强制限定在本店（即使伪造请求传入其他门店 ID 也无效）；
- 定价、会员等级、提成矩阵、跨店调动、删除报表仅总部可操作；
- 已双方签字锁定的班次对任何角色只读。

## 目录结构

```
server/
  server.js   HTTP 服务、鉴权、全部 REST API、汇总口径
  db.js       JSON 持久化（写入 data/db.json）
  seed.js     演示数据生成（确定性随机，可重复生成）
  util.js     会员折扣/提成/交班合计等业务规则（服务端与种子共用）
public/
  index.html
  css/style.css
  js/app.js   登录、路由、全部页面与交互（含手写签字板）
  js/chart.js 手写 SVG 图表（折线/面积、排行条、环形、堆叠条）
data/db.json  运行后自动生成（可随时 npm run reset）
```

## 技术说明

- 金额以整数元存储；会员价 = 挂牌价 × 等级折扣（四舍五入到元），折扣额单独留痕。
- 历史单据永久保留成交时的项目名、价格、提成比例与技师等级，总部事后调价/调比例不会篡改历史报表。
- 数据保存在单个 JSON 文件（适合演示与中小规模原型）；如需上生产，可将 `server/db.js` 替换为真正的数据库而不动业务层。
